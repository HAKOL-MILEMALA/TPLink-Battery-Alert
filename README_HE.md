# התראת סוללת TP-Link M7200 לרכב

## הורדה ישירה – הגרסה האחרונה

**[⬇️ הורדת M7200 Car Alert (APK)](https://github.com/HAKOL-MILEMALA/M7200CarAlert/releases/latest/download/M7200-Car-Alert.apk)**

זהו קישור קבוע להפצה: אפשר לשלוח אותו בוואטסאפ, להציג באתר או לשמור במועדפים. הוא תמיד מפנה לקובץ ההתקנה של הגרסה היציבה האחרונה.

[לכל הגרסאות, פרטי השחרור והיסטוריית העדכונים](https://github.com/HAKOL-MILEMALA/M7200CarAlert/releases)


אפליקציית Android למולטימדיה TS10S עם Android 12. היא קוראת את אחוז הסוללה של TP-Link M7200 דרך רשת ה-Wi-Fi המקומית, ומציגה התראה בולטת אחת כשהסוללה מגיעה ל-10% ומטה.

## מה האפליקציה עושה

- בודקת את הנתב פעם בדקה.
- מציגה התראת Android בולטת כאשר הסוללה מגיעה ל-10% ומטה, כל עוד היא אינה בטעינה.
- ההתראה נשלחת פעם אחת בלבד בכל מחזור פריקה, ומתאפשרת מחדש רק אחרי שהסוללה עולה ל-15% ומעלה.
- אין היסטוריה, ETA או נודניק.
- שירות הניטור ממשיך לפעול ברקע ומופעל מחדש לאחר אתחול המולטימדיה, לאחר שהופעל פעם אחת ידנית.
- בקשות הניטור המקומיות מנותבות דרך רשת ה-Wi-Fi של הסטיק, גם אם Android מסמן אותה כרשת ללא אינטרנט.
- סיסמת הנתב נשמרת מוצפנת באמצעות Android Keystore (AES-GCM).
- מסך האפליקציה מציג את הגרסה המותקנת, קישור לפרויקט GitHub וכפתור לבדיקת עדכונים.
- בדיקת עדכונים אוטומטית מתבצעת לכל היותר פעם בשבוע, בין אם האפליקציה נפתחת ובין אם שירות הניטור פועל ברקע. מסך האפליקציה ושירות הרקע משתפים את אותו מועד בדיקה כדי למנוע בדיקות כפולות. אפשר לבדוק ידנית בכל רגע.
- אם נמצאה גרסה חדשה, האפליקציה מורידה APK מה-Release הרשמי, בודקת SHA-256 כאשר GitHub מספק אותו, ומעבירה את ההתקנה למתקין Android. המשתמש עדיין מאשר את ההתקנה במערכת.

## דרישות והנחות

- נכתב עבור Android 12 (API 31), עם תמיכה מ-Android 8 ומעלה.
- שירות החזית מוגדר מסוג `dataSync`. באנדרואיד 12 עם `targetSdk 32` זו אינה דרישת חובה, אך ההגדרה מכינה את המניפסט לדרישות החדשות יותר.
- מניח שהנתב הוא TP-Link M7200 ושכתובת הניהול שלו היא `192.168.0.1`.
- המולטימדיה חייבת להיות מחוברת ל-Wi-Fi של ה-M7200 כדי לקרוא את מצב הסוללה.
- קריאת הסוללה המקומית אינה דורשת אינטרנט. בדיקת עדכונים והורדת APK דורשות חיבור אינטרנט פעיל; אם אין אינטרנט, הניטור המקומי ממשיך כרגיל והעדכון ייבדק שוב מאוחר יותר או בלחיצה ידנית.

## הפעלה ראשונית במולטימדיה

1. התקן את קובץ ה-APK.
2. פתח את האפליקציה פעם אחת.
3. ודא שהמולטימדיה מחוברת לרשת ה-Wi-Fi של ה-M7200.
4. הזן את סיסמת הניהול של ממשק הנתב (לא את סיסמת ה-Wi-Fi, אלא אם הן זהות אצלך).
5. לחץ על **שמור והפעל ניטור**.
6. אשר שהתראת הפעילות השקטה מופיעה בשורת ההתראות.
7. ודא שבהגדרות ההתראות של Android מותר לאפליקציה להציג התראות קופצות (Heads-up / Pop on screen).

אם הקושחה של המולטימדיה כוללת הגדרת Autostart או ניהול אגרסיבי של סוללה, יש לאפשר לאפליקציה הפעלה אוטומטית ולבחור עבורה מצב ללא הגבלת סוללה. שמות התפריטים משתנים בין גרסאות TS10S.

## עדכוני APK וחתימה קבועה

כדי ש-Android יאפשר להתקין עדכון מעל האפליקציה הקיימת, כל גרסה חייבת להיחתם באותו מפתח פרטי. המפתח אינו נשמר במאגר הציבורי.

לפני הבנייה הראשונה של גרסה 1.0.2 יש להוסיף פעם אחת Secret למאגר:

1. פתח ב-GitHub את **Settings → Secrets and variables → Actions**.
2. לחץ **New repository secret**.
3. בשדה Name כתוב בדיוק `M7200_SIGNING_BUNDLE_B64`.
4. בשדה Secret הדבק את כל התוכן של קובץ `M7200_SIGNING_BUNDLE_B64.txt` שסופק לך בשיחה.
5. שמור את ה-Secret. אין להעלות את הקובץ או את תיקיית `signing/` למאגר ואין לשתף את המפתח.

אחרי שה-Secret קיים, כל Push רלוונטי או הפעלה ידנית של Workflow יבנו APK מסוג Release חתום ויפרסמו קובץ APK אחד בלבד בשם `M7200-Car-Alert.apk`. כל גרסה נשמרת ב-Release נפרד עם תג הכולל את מספר הגרסה, ולכן אין צורך לשכפל את קובץ ההתקנה או לשנות את קישור ההורדה הקבוע. שם הגרסה נקרא אוטומטית מתוך `app/build.gradle`.

בעת הכנת גרסה חדשה יש להעלות גם את `versionCode` וגם את `versionName` ב-`app/build.gradle`. בלי הגדלת מספר הגרסה, האפליקציה לא תציע עדכון.

**מעבר חד-פעמי מגרסה 1.0.1:** ה-APK הראשון שהופק ב-GitHub Actions נחתם במפתח Debug זמני של שרת הבנייה. לכן אי אפשר להתקין את 1.0.2 מעל אותו APK. אם כבר התקנת את 1.0.1, יש להסיר אותה ולהתקין את 1.0.2 מחדש (הסרת אפליקציה מוחקת את הסיסמה וההעדפות השמורות). אחרי ההתקנה הראשונה של 1.0.2, כל העדכונים העתידיים ייחתמו באותו מפתח ויוכלו להתקין מעל הקיים.

## בניית APK ב-GitHub

1. ודא שה-Secret `M7200_SIGNING_BUNDLE_B64` קיים (ראו סעיף חתימה קבועה).
2. פתח את לשונית **Actions** במאגר.
3. בחר **Build M7200 Car Alert APK** ולחץ **Run workflow**, או בצע Commit/Push.
4. בסיום הבנייה היכנס ללשונית **Releases** והורד את קובץ ה-APK הישיר. נשמר גם Artifact להורדה מתוך ריצת הבנייה.

## התנהגות במקרה של ניתוק

אם ה-Wi-Fi של המולטימדיה מתנתק מה-M7200, אין לאפליקציה דרך לקרוא את אחוז הסוללה באותו רגע. היא תמתין ותנסה שוב פעם בדקה. אם ה-M7200 נשאר דולק ומחובר לרשת אך נותק מהמטען, הניטור ממשיך כרגיל ויתריע כשהסוללה תרד ל-10%.

## הערות Android 12 / TS10S

- באנדרואיד 12 אין הרשאת זמן-ריצה נפרדת להתראות `POST_NOTIFICATIONS`; היא נוספה באנדרואיד 13. עם זאת, ערוץ ההתראה חייב להישאר מוגדר כחשיבות גבוהה, ובהגדרות המולטימדיה צריך לאפשר לו התראות קופצות.
- התקנת עדכון דורשת לאפשר לאפליקציה **Install unknown apps / התקנה ממקור זה**. Android יציג את בקשת האישור ויפתח את מתקין החבילות; האפליקציה אינה מתקינה את עצמה בשקט.
- עדכון דורש אינטרנט פעיל. היעדר אינטרנט אינו מפריע לקריאת הסוללה המקומית.
- ערוץ התראה שכבר נוצר לא מקבל שינוי חשיבות מתוכנה בעדכון. אם ההתראה אינה קופצת, יש לבדוק את הגדרות הערוץ במערכת עצמה.
- יצרני מולטימדיה עשויים להגביל הפעלה אוטומטית או שירותי רקע. יש לאפשר Autostart/Background activity ולהחריג את האפליקציה ממגבלות חיסכון בסוללה, אם האפשרויות קיימות.
- סוג `dataSync` כפוף למגבלת זמן של 6 שעות לשירותי חזית רק באפליקציות שמכוונות ל-Android 15 (API 35) ומעלה. הפרויקט נשאר כרגע עם `targetSdk 32`.
